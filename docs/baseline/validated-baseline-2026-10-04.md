# 财务预审 POC 已验收工程基线（2026-10-04）

## 1. 基线定位与边界

本基线是 WSL2 本地、单人、人工在环的财务预审 POC。除经用户明确触发的文件接入外，案例、申请和实验规则均为 `MOCK`。系统输出是预审报告和评测证据，不是 OA 审批、付款指令或真实财务制度结论。

本次 Git 提交固定源码、迁移、测试、合成案例和设计文档。运行数据库、原始上传材料、解析工件、评测运行产物、导出报告、`.env` 及密钥不进入版本库。

## 2. 已验收行为

### 2.1 文件接入与票据加工

- 页面由用户显式上传材料，系统保存文档与解析任务 ID，提交 COS/MinerU，并通过手动同步恢复状态。
- 成功解析后可保存工件、执行发票字段加工和票内检查；页面刷新不依赖 Streamlit 会话猜测任务状态。
- 已在授权样本上完成一次上传、解析、结构化的完整链路验证。
- 提交失败和 `submission_unknown` 有可恢复记录；长期 `pending` 的自动超时处置仍未完成。

### 2.2 业务预审与报告

- Mock 申请作为独立快照输入，申请金额不会从发票总额自动复制。
- 现有服务能生成不可变的 `PASS`、`REVIEW` 和 `MISSING_EVIDENCE` 报告。
- 空的申请金额、币种或事由按缺失事实进入预审；非空但格式错误的金额、币种等在保存前拒绝。
- 报告保存申请和票据快照、逐项检查、Evidence、规则/基线/提示词版本、模型元数据和输入指纹。
- 报告详情读取保存时结果，不在页面重新计算；业务反馈以追加记录存在，不覆盖原报告。

页面联调留下三份业务报告：

- `TEST-PASS-001`：`PASS`
- `TEST-REVIEW-001`：`REVIEW`，并追加了一条业务反馈
- `TEST-MISSING-001`：`MISSING_EVIDENCE`

`TEST-INVALID-001` 使用非空但格式错误的输入，页面正确拒绝，未创建业务报告。

### 2.3 Evaluation Experiment V1

- 评测工作区与业务演示数据库隔离，以 `EvaluationCase → InputRevision → EvaluationRun` 记录一次行为。
- `HumanEvaluation` 作为追加证据，可定位最终决策、Check、字段或执行过程，不覆盖系统输出。
- 无报告的技术失败也能形成 Run 和人工评价。
- 同一 Case 可通过新 InputRevision 表达补正输入，并以 `parent_run_id` 关联前后运行。
- 严格金额相等与明确标记为 Mock 的容差策略均真正参与执行；运行保存输入、源码、策略实现和参数指纹。
- RunComparison 先记录输入、规则、模型和实现等变化维度，再展示结果差异。
- 页面在运行前展示所选修订的关键输入摘要，减少选错修订或误读金额的风险。

页面联调最终记录：4 个 Case、5 个 Revision、6 次 Run、4 条人工评价和 2 条运行比较。四类情况均已被人工评价：`PASS` 漏检、`REVIEW`、`MISSING_EVIDENCE`、无报告技术失败。补正输入比较和规则变化比较均完成。

## 3. 验证证据

离线回归命令：

```bash
.venv/bin/python -m unittest discover -s prototype/tests
```

本基线在 2026-10-04 通过 99 项测试。测试覆盖应用服务、文件接入、票据加工、预审、报告导出、Streamlit 页面辅助逻辑、Evaluation V1 和公开配置边界。

页面联调涉及的数据库和评测产物只保存在被 `.gitignore` 排除的 `var/` 下，不作为测试夹具或 Git 基线的一部分。

## 4. 已知限制

- 真实审核规则、制度生效范围、例外、人员/部门/职级和人工复核口径仍需真实财务案例确认。
- 当前主链是一份申请关联一张发票；没有多材料、金额求和/分摊或跨材料通用一致性机制。
- 业务报告尚未采用 InputRevision，也没有业务输入补正后的父子 Run 关系；该能力目前只在独立评测实验中存在。
- 尚未建设认证、RBAC、并发控制、隐私与保留策略、生产部署、监控告警和 OA 写回。
- 不提供发票真伪、重复报销、舞弊、税务或法律结论。
- Mock 金额容差只用于架构实验，不代表任何公司制度。

## 5. 本地复现与敏感信息边界

1. 复制 `.env.example` 为本地 `.env`，按需要填写环境变量。
2. 安装 `requirements.txt` 中的依赖。
3. 运行上面的离线测试；离线测试不需要 COS、MinerU 或在线模型凭证。
4. 只有验证真实文件接入时才配置 COS/MinerU；只有显式启用在线语义模型时才配置相应模型参数。

版本库不得包含 `var/`、SQLite 运行库、原始上传文件、解析工件、评测运行产物、导出报告、`.env`、Token、Secret 或签名 URL。
